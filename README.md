# Alflag provisioning

This repository is the Ansible project root for the managed hosts. It contains the inventory,
playbooks, roles, Ansible collection requirements, and local and CI validation commands.

## Layout

```text
ansible.cfg
inventories/default/
playbooks/
roles/
collections/requirements.yml
mise.toml
mise.lock
requirements-dev.txt
```

The installed collection tree under `collections/ansible_collections/` is generated by setup and
is ignored by Git. Atlas is part of the foundation for every host in the `default` inventory.

## Set up

```bash
mise install
mise run setup
mise run check
```

`mise run setup` creates `.venv`, installs the validation tools from `requirements-dev.txt`, and
installs the collections declared in `collections/requirements.yml`.

`mise run check` runs YAML lint, Ansible lint, and syntax checks for `site.yml`, `bootstrap.yml`,
and `cloudflare.yml`. These checks do not connect to managed hosts.

## Playbooks

- `playbooks/bootstrap.yml` bootstraps hosts and installs the Atlas host runtime.
- `playbooks/site.yml` converges the shared foundation, control-plane lifecycle boundary, DNS, web,
  MySQL, monitoring, and NetBox components.
- `playbooks/cloudflare.yml` converges explicit host-side Cloudflare components.

Run Ansible from the repository root so that `ansible.cfg` and the default inventory are used. Use
check mode and an explicit target before applying changes:

```bash
.venv/bin/ansible-playbook --check --diff playbooks/site.yml --limit <target>
.venv/bin/ansible-playbook playbooks/site.yml --limit <target>
```

Use the corresponding playbook path for bootstrap or Cloudflare host-side changes.

## Monitoring discovery

On monitoring hosts, Prometheus generates node-exporter file service discovery from members of
the configured inventory group. A host is included when `node_exporter_enabled` is true and it
defines `network_ipv4_address` or `ansible_host`.

Blackbox HTTP targets are explicit inventory input because Cloudflare routes and public endpoints
are outside this repository's responsibility. Define Prometheus file-SD records with
`prometheus_blackbox_http_targets` when an endpoint is ready to monitor:

```yaml
prometheus_blackbox_http_targets:
  - targets:
      - https://service.example/healthz
    labels:
      service: service
```

## NetBox

`netbox01` is a Proxmox VM on the MGMT network at `10.10.10.63`. Caddy accepts internal HTTP on
port 80 and serves NetBox static files directly, while proxying application requests to the
loopback-only Gunicorn listener at `127.0.0.1:8001`. The service is not published through
Cloudflare or public DNS. NetBox is installed from the pinned native release `4.6.7` under
`/opt/netbox` with its Python virtual environment, PostgreSQL, Redis, Gunicorn, and RQ worker
managed by systemd.

HTTP frontend standard: new HTTP services use the reusable `roles/components/caddy/` component.
The existing `services/web` nginx workload is intentionally unchanged; its migration is a separate
task and is not a reason to add nginx to new service roles.

Before converging `netbox01`, create the ignored local secret input file
`inventories/default/group_vars/all/secrets.yml` with these required variables:

```yaml
netbox_secret_key: <generated value>
netbox_api_token_pepper: <generated value>
netbox_postgres_password: <generated value>
netbox_redis_password: <generated value>
```

Use check mode and then apply the bootstrap and service convergence explicitly:

```bash
.venv/bin/ansible-playbook --check --diff playbooks/site.yml --limit netbox01
.venv/bin/ansible-playbook playbooks/bootstrap.yml --limit netbox01
.venv/bin/ansible-playbook playbooks/site.yml --limit netbox01
```

After the services are healthy, create the first administrator interactively on `netbox01`:

```bash
sudo -u netbox /opt/netbox/venv/bin/python \
  /opt/netbox/netbox/manage.py createsuperuser
```

Open `http://10.10.10.63/` from the MGMT network. The role deliberately does not create a default
administrator, API token, inventory objects, DNS records, or Cloudflare exposure.

## Secrets

Do not commit passwords, tokens, private keys, vault passwords, or rendered secret variables.
The ignored paths `inventories/**/group_vars/all/secrets.yml` and
`inventories/**/group_vars/all/secrets/` are available for operator-managed local secret input.
